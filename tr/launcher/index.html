Yenilikler · Sürüm 5.1.1

Corvus Store 5.1.1 and Corvus Agent 5.1.1 keep themselves up to date, and a retired model now leaves players' computers only after their server has let it go.

Corvus Agent now updates itself. When a new version is published, the agent downloads it, checks it, and waits until no player is online; then it stops the server cleanly, replaces itself, starts again and brings the server back. The previous copy is kept next to it as corvus-agent.jar.bak. If the new version does not start, the old one carries on. You can turn this off with the autoUpdateAgent setting.

Corvus Store now updates the Corvus Agent on the same PC by itself, with no click: if the Store set the agent up, it replaces the agent when a new version is out and restarts it when no player is online. With players online it waits for the next check.

A retired model is removed from players' computers only after their server has removed it, or on the removal date published on the website, whichever comes first. In Corvus Store 5.1.0 ASTRAEA left players' mods folders at once, while servers whose agent had not been updated still asked for it, so players could not join ("ASTRAEA not installed"). Corvus Store 5.1.1 waits for the server.

Fixes: an agent started in a console window now restarts itself if the new version fails to start, and its timer is stopped before the switch.

What to do once: nothing, if Corvus Store on that PC set the agent up. Otherwise press Update once on the Corvus Agent card (or replace corvus-agent.jar by the 5.1.1 jar and restart the agent). From 5.1.1 on the agent updates itself.

Verified: 1,321 unit tests pass (497, 198 and 626 in the three modules). On a real Minecraft 26.3 server on macOS, Corvus Agent 5.1.1 updated itself to a newer test version, in the background and in a console window, and Corvus Store 5.1.1 replaced and restarted an Agent 5.0.2 it had set up, which then removed ASTRAEA while every other mod stayed byte-identical. Not verified, and worth saying: nothing was run on Windows; going back from Agent 5.1 to 5.0.2 needs the difficulty line removed from the agent settings by hand; when the Store replaces the agent it keeps no .bak copy; the words in the eleven languages other than English and Japanese were translated plainly and have not been read by a native speaker.

Kılavuz

Corvus, modlarınızı otomatik olarak güncel tutan küçük bir masaüstü uygulamasıdır. Güncel sürümü bu Wiki'den öğrenir, güncellemeleri sizin için indirir ve mods klasörünüze dokunmadan önce indirdiği her dosyayı burada yayımlanan SHA-256 sağlama toplamıyla doğrular. Güvendiği tek kaynak bu Wiki'dir.

Bu kılavuz Corvus'un önceki sürümleri için yazıldı. Corvus Store 3.0'ın ekranları yeni; bazı adımlar farklı olabilir.

Corvus nedir, neden yapıldı

Modları elle güncel tutmak, her sürümde indirme sayfasına yeniden gitmek, sürüm numaralarını karşılaştırmak, yeni bir dosya indirmek ve onu doğru klasöre koymak demektir. Corvus bunu otomatikleştirir: bu Wiki'nin sürüm bildirimini okur, kurulu olanla karşılaştırır ve yalnızca değişeni getirir.

Başlatıcının yaptığı her indirme, kullanılmadan önce bu Wiki'nin yayımladığı SHA-256 sağlama toplamıyla doğrulanır. İndirilen dosya eşleşmezse başlatıcı onu kurmaz. "Güncel" sürümün hangisi olduğu konusunda başlatıcının tek doğruluk kaynağı bu Wiki'dir.

Corvus nasıl kurulur

Corvus, bu Wiki'nin indirme sayfasından iki biçimde edinilebilir:

  • İşletim sistemine özel yerel kurucular (Windows için .msi, macOS için .dmg, Linux için .deb) — sıradan bir masaüstü uygulaması gibi kurulur, Java gerekmez. Henüz kod imzalaması yapılmadığı için ilk açılışta işletim sistemi bir uyarı gösterir. macOS'ta çift tıklamak yerine uygulamaya sağ tıklayıp «Aç» seçeneğini kullanın. Windows'ta SmartScreen uyarısında «Ek bilgi» → «Yine de çalıştır» seçeneğini kullanın.
  • Platformdan bağımsız jar corvus-5.1.1.jar — aynı 1 dosya Windows, macOS ve Linux'un hepsinde çalışır, ancak sisteminizde önceden Java 25 veya üzeri kurulu olmalıdır. Çift tıkladığınızda açılmıyorsa, dosyayı indirdiğiniz klasörde bir terminal (ya da komut istemi) açıp java -jar corvus-5.1.1.jar komutunu çalıştırın.
Mevcut MOD paketi klasörünü göstermek

Modları zaten elle kurduysanız baştan başlamanız gerekmez. İlk çalıştırmada başlatıcı, yeni bir klasör oluşturmak yerine modlarınızın zaten bulunduğu klasörü seçmenize izin verir. Mevcut mods klasörünüzü gösterin; başlatıcı bundan sonra o kurulumu yönettiği kurulum olarak ele alır.

Otomatik ve elle güncelleme modu arasındaki fark

Otomatik güncelleme modunda başlatıcı, bu Wiki'deki yayın bilgisini kendisi denetler ve yeni bir sürüm yayımlanır yayımlanmaz kurar. Siz hiçbir şey yapmasanız da paket klasörünüz her zaman güncel kalır.

Elle güncelleme modunda başlatıcı güncelleme olup olmadığını yine denetler, ancak indirme veya kurma işlemine geçmeden önce sizin onayınızı bekler. Oyun sırasında güncellemenin araya girmesini istemediğiniz durumlar gibi, güncellemenin zamanını kendiniz seçmek istediğinizde işe yarar.

Güncellemenin gerçekten uygulandığını doğrulama

1.1.0 sürümünden itibaren, Update düğmesine bastığınızda yeni MOD dosyaları doğrudan paketinizin mods klasörüne yazılır. Başlatıcı, güncellemeden sonra klasörün içeriğini gerçekten yeniden denetleyip beklenen dosyaların orada olduğunu doğrulamadan «Update complete» yazısını göstermez. İşlemin ortasında bir şey başarısız olursa, sahte bir başarı bildirimi yerine başarısızlık olarak raporlanır.

macOS'ta bunu kendiniz doğrulama yöntemi: Genel ekranında gösterilen klasörü açın (Finder'da ⌘+⇧+G tuşlarına basıp yolu yapıştırın), mods klasörünün içine bakın ve Update öncesiyle sonrasında her cherry-*.jar dosya adındaki sürüm numarasını karşılaştırın.

1.1.0'dan eski bir başlatıcı sürümünün en son dokunduğu bir paket klasöründen güncelleme yapıyorsanız, yalnızca ilk 1 seferde o MOD'un eski sürüm numaralı jar dosyası yeni jar'ın yanında kalabilir (daha eski başlatıcılarda, hangi dosyaları kendisinin yerleştirdiğine dair bir kayıt yoktu). Sonraki güncellemelerden itibaren bu durum kendiliğinden düzelir. Hemen rahatsız ediyorsa, yenisinin orada olduğunu doğruladıktan sonra eski sürüm numaralı cherry-*.jar dosyasını elle silmenizde bir sakınca yok.

Güncelleme başarısız olduğunda yedekten geri yükleme

Güncelleme sonucunda MOD'da bir aksaklık gibi istemediğiniz bir duruma düşerseniz ya da güncellemeyi geri almak isterseniz diye başlatıcı, güncelleme öncesindeki paket durumunu yedek olarak saklar. Dosyaları elle düzeltmeye çalışmak yerine, başlatıcının geri yükleme işlevini kullanarak paket klasörünü yedeğin alındığı ana geri döndürün.
