新機能 · バージョン 5.5.1311

Corvus Store 5.5.1311 and Corvus Agent 5.5.1311 bring the following.

Corvus Store now also downloads Fabric API, which Punchy! needs, straight from Modrinth when it is missing from the mods folder. This happens only when you press Install for Punchy!, and the confirmation says so. A Fabric API you already have is never touched. If Fabric API cannot be downloaded or fails its check, Punchy! is not installed and nothing is left behind.

On macOS, Corvus Store follows the system's Reduce Transparency, Increase Contrast and Reduce Motion settings while it is running, without a restart. It shows the number of available updates and the progress of a download on its Dock icon. It gives a trackpad tap as the sliders click into each step and when you choose a model. It no longer waits for a macOS permission question before its window appears.

Corvus Agent 5.5.1311 has no functional change.

Known limits: the macOS features were checked on one Mac with test instruments, not by long use. Fabric API downloading was checked with a local stand-in, not yet with a real download through the Store. Windows and Linux do not use the macOS features.

ガイド

Corvus は、導入した MOD を自動で最新に保つ小さなデスクトップアプリです。この Wiki で現行版を確認し、更新をダウンロードし、mods フォルダーに手を付ける前に、ダウンロードしたファイルをここに公開している SHA-256 と照合します。信頼するのはこの Wiki だけです。

このガイドは以前のバージョンの Corvus のために書かれました。Corvus Store 3.0 は画面が新しくなっているため、手順が異なる場合があります。

Corvus とは何か、なぜ作られたのか

MOD を手で最新に保つには、リリースのたびにダウンロードのページを見に行き、バージョン番号を見比べ、新しいファイルをダウンロードして、正しいフォルダーに入れ直すことになります。Corvus はそれを自動でやります。この Wiki のリリース一覧(マニフェスト)を読み、いま導入されているものと突き合わせ、変わった分だけを取ってきます。

ランチャーが行うダウンロードはすべて、使う前に、この Wiki が公開している SHA-256 チェックサムと照合されます。一致しなければ、ランチャーは導入しません。「現行のリリース」が何かについて、ランチャーが信じるのはこの Wiki だけです。

Corvus の入れ方

Corvus は、この Wiki のダウンロードのページから、二つの形で入手できます。

  • OSごとのネイティブインストーラー(Windows用 .msi・macOS用 .dmg・Linux用 .deb) ―― 通常のデスクトップアプリと同じ手順で導入でき、Java は不要です。まだコード署名を行っていないため、初回起動時にOSから警告が表示されます。macOSでは、ダブルクリックの代わりにアプリを右クリックして「開く」を選んでください。Windowsでは、SmartScreenの警告で「詳細情報」→「実行」を選んでください。
  • クロスプラットフォームのjar corvus-5.5.1311.jar ―― 同じ1つのファイルが Windows・macOS・Linux のいずれでも動きますが、あらかじめ Java 25 以降が導入されている必要があります。ダブルクリックで開かない場合は、ダウンロードしたフォルダーでターミナル(またはコマンドプロンプト)を開き、java -jar corvus-5.5.1311.jar を実行してください。
既存の MOD パックフォルダーを指定する

すでに MOD を手で入れている場合も、やり直す必要はありません。初回起動で、新しく作る代わりに、MOD が入っているフォルダーを選べます。既存の mods フォルダーを指定すると、以後 Corvus はそれを自分が管理する導入先として扱います。

自動更新モードと手動更新モードの違い

自動更新モードでは、ランチャーがこの Wiki のリリース情報を自ら確認し、新しいバージョンが公開され次第インストールします。何もしなくてもパックフォルダーは常に最新の状態に保たれます。

手動更新モードでは、ランチャーは更新の有無を確認しますが、ダウンロードやインストールを行う前にあなたの確認を待ちます。プレイ中に更新が割り込むのを避けたいときなど、更新のタイミングを自分で選びたい場合に便利です。

更新が本当に反映されたかの確認方法

バージョン1.1.0以降、Update を押すと新しいMODファイルがパックの mods フォルダーに直接書き込まれます。更新後にフォルダーの中身を 実際に再確認し、期待通りのファイルが存在することを確認できるまで「Update complete」とは表示されません。途中で何か失敗した場合は、偽の成功表示ではなく失敗として報告されます。

macOSで実際に確認する方法: 「一般」に表示されているフォルダーを開き(Finderで ⌘+⇧+G を押してパスを貼り付け)、mods の中を見て、Update前後で各 cherry-*.jar ファイル名内の版数を確認してください。

1.1.0より前のバージョンのランチャーで最後に触られたパックフォルダーから更新する場合、最初の1回だけ、そのMODの古い版数の jar が新しい jar と並んで残ることがあります(それ以前のランチャーには、自分がどのファイルを配置したかの記録が無かったためです)。次回以降の更新からは自動的に解消します。すぐに気になる場合は、新しい方の存在を確認した上で、古い版数の cherry-*.jar を手動で削除しても問題ありません。

更新に失敗したときにバックアップから復元する

更新の結果、MOD の不具合など望まない状態になってしまった場合や、更新を取り消したい場合のために、ランチャーは更新前のパックの状態をバックアップとして保持しています。ファイルを手作業で直そうとするのではなく、ランチャーの復元機能を使ってパックフォルダーをバックアップ時点の状態へ戻してください。
