新機能 · バージョン 5.0.0

Corvus Store 5.0.0 and Corvus Agent 5.0.0 take care of a Minecraft server you host yourself, so that you no longer have to.

Corvus Agent now runs the server for you. When an update is published it waits until nobody is playing, backs up the world, stops the server, swaps the mods, starts it again and checks that it answers; if it does not, it puts the old mods back and starts it again. It backs the world up on its own every six hours by default (keeping the newest seven), pausing the game's saving while it copies so the copy is never half-written, and it can put any of those backups back with one confirmation, taking a fresh backup first. If you use playit.gg it opens the tunnel once the server is up, and if playit is stopped it tries once to start it. Everything it does is written down.

Corvus Store has a new screen for this: Agents (Corvus Studio). The Dashboard shows the server, the tunnel, the backups and any update at a glance, with Start, Stop, Restart, Back up now and Update now. Activity lists what the agent did, in your language, and lets you restore a backup or read the logs. Settings let you turn automatic updates and automatic backups on or off, choose how often to back up and how many to keep, start the server when Corvus Store opens, keep it running when Corvus Store quits (the default), and open Corvus Store when the computer starts. Together that is: switch the computer on, and the server and the tunnel come up by themselves.

If you set the agent up with an earlier version, 5.0.0 picks up where it was. If the old agent is still running the server, Corvus Agent 5 does not start a second one; it says so, and takes over once the old window is closed. A start script that Corvus wrote is updated to the new agent; one you changed is left alone, and the Store tells you the one line to change.

Verified: 1,212 unit tests pass (474, 149 and 589 in the three modules), with the compiler set to refuse any warning. Corvus Agent 5 was run against a real Fabric 26.3 server on macOS: it started the server, took a backup through Corvus Store's controls (saving paused and resumed), installed an update in the order above, restored a backup after asking for confirmation, refused to start a second server while an Agent 4.1 ran the same folder and took over when it stopped, and shut everything down cleanly. On Windows (CI), the installed Corvus Store started the agent, the agent kept running after the Store quit, its controls answered, a second agent in the same folder refused to start, and the "open at start-up" switch wrote and removed the correct entry; the official playit installer was installed and its real output is what the agent reads. Not verified, and worth saying: nobody has yet pressed the new buttons in a real Corvus Store window on Windows, or run a real Minecraft server on Windows with it; a playit account was never claimed here, so a live tunnel, the wording playit prints while running, and whether playit can be started without administrator rights on your PC are not confirmed (if it cannot, the Dashboard tells you); "open at start-up" was not tried through a real sign-in; the words in the eleven languages other than English and Japanese were translated plainly and not read by a native speaker.

ガイド

Corvus は、導入した MOD を自動で最新に保つ小さなデスクトップアプリです。この Wiki で現行版を確認し、更新をダウンロードし、mods フォルダーに手を付ける前に、ダウンロードしたファイルをここに公開している SHA-256 と照合します。信頼するのはこの Wiki だけです。

このガイドは以前のバージョンの Corvus のために書かれました。Corvus Store 3.0 は画面が新しくなっているため、手順が異なる場合があります。

Corvus とは何か、なぜ作られたのか

MOD を手で最新に保つには、リリースのたびにダウンロードのページを見に行き、バージョン番号を見比べ、新しいファイルをダウンロードして、正しいフォルダーに入れ直すことになります。Corvus はそれを自動でやります。この Wiki のリリース一覧(マニフェスト)を読み、いま導入されているものと突き合わせ、変わった分だけを取ってきます。

ランチャーが行うダウンロードはすべて、使う前に、この Wiki が公開している SHA-256 チェックサムと照合されます。一致しなければ、ランチャーは導入しません。「現行のリリース」が何かについて、ランチャーが信じるのはこの Wiki だけです。

Corvus の入れ方

Corvus は、この Wiki のダウンロードのページから、二つの形で入手できます。

  • OSごとのネイティブインストーラー(Windows用 .msi・macOS用 .dmg・Linux用 .deb) ―― 通常のデスクトップアプリと同じ手順で導入でき、Java は不要です。まだコード署名を行っていないため、初回起動時にOSから警告が表示されます。macOSでは、ダブルクリックの代わりにアプリを右クリックして「開く」を選んでください。Windowsでは、SmartScreenの警告で「詳細情報」→「実行」を選んでください。
  • クロスプラットフォームのjar corvus-5.0.0.jar ―― 同じ1つのファイルが Windows・macOS・Linux のいずれでも動きますが、あらかじめ Java 25 以降が導入されている必要があります。ダブルクリックで開かない場合は、ダウンロードしたフォルダーでターミナル(またはコマンドプロンプト)を開き、java -jar corvus-5.0.0.jar を実行してください。
既存の MOD パックフォルダーを指定する

すでに MOD を手で入れている場合も、やり直す必要はありません。初回起動で、新しく作る代わりに、MOD が入っているフォルダーを選べます。既存の mods フォルダーを指定すると、以後 Corvus はそれを自分が管理する導入先として扱います。

自動更新モードと手動更新モードの違い

自動更新モードでは、ランチャーがこの Wiki のリリース情報を自ら確認し、新しいバージョンが公開され次第インストールします。何もしなくてもパックフォルダーは常に最新の状態に保たれます。

手動更新モードでは、ランチャーは更新の有無を確認しますが、ダウンロードやインストールを行う前にあなたの確認を待ちます。プレイ中に更新が割り込むのを避けたいときなど、更新のタイミングを自分で選びたい場合に便利です。

更新が本当に反映されたかの確認方法

バージョン1.1.0以降、Update を押すと新しいMODファイルがパックの mods フォルダーに直接書き込まれます。更新後にフォルダーの中身を 実際に再確認し、期待通りのファイルが存在することを確認できるまで「Update complete」とは表示されません。途中で何か失敗した場合は、偽の成功表示ではなく失敗として報告されます。

macOSで実際に確認する方法: 「一般」に表示されているフォルダーを開き(Finderで ⌘+⇧+G を押してパスを貼り付け)、mods の中を見て、Update前後で各 cherry-*.jar ファイル名内の版数を確認してください。

1.1.0より前のバージョンのランチャーで最後に触られたパックフォルダーから更新する場合、最初の1回だけ、そのMODの古い版数の jar が新しい jar と並んで残ることがあります(それ以前のランチャーには、自分がどのファイルを配置したかの記録が無かったためです)。次回以降の更新からは自動的に解消します。すぐに気になる場合は、新しい方の存在を確認した上で、古い版数の cherry-*.jar を手動で削除しても問題ありません。

更新に失敗したときにバックアップから復元する

更新の結果、MOD の不具合など望まない状態になってしまった場合や、更新を取り消したい場合のために、ランチャーは更新前のパックの状態をバックアップとして保持しています。ファイルを手作業で直そうとするのではなく、ランチャーの復元機能を使ってパックフォルダーをバックアップ時点の状態へ戻してください。
