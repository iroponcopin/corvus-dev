新功能 · 版本 3.0.2

Corvus Store 3.0.2 is a small release with two changes.

Tsubomi can now be installed from the Store. Tsubomi is published as one jar rather than a package of several, and Corvus Store 3.0.0 and 3.0.1 did not know that shape, so its card said "Coming soon". The card now has a GET button like OUKA, Cherry, ASTRAEA and Aureum have. Pressing it downloads the jar, checks its size and SHA-256 against the site, and puts it in your mods folder; once it is installed, Tsubomi updates itself in place, and an installed copy is found by what the jar is, not by what the file is called. Tsubomi cannot run beside Alpha: its own jar says so, and Minecraft would refuse to start. So if your mods folder holds any Alpha module, the Store says so in one plain sentence that names the jars, and changes nothing. That applies to updates too.

The icons are the new ones. OUKA, Cherry, Aureum and Corvus Store itself now show the same icons as the website; they are the website's own files, not redrawn copies, and the big pictures on the Today cards of OUKA, Cherry and Aureum are the website's new banners. In a language that reads right to left the banner is arranged for it, with the emblem on the left and drawn as it is, not mirrored. The old marks are gone from the application, from the macOS, Windows and Linux installers' icons, and from the Today cards. One thing to know: the largest size inside the macOS icon is the 512 pixel logo enlarged, because 512 pixels is all the studio supplied.

Everything else is 3.0.1.

Verified: 933 unit tests pass, with the compiler set to refuse any warning, and two clean builds made byte-identical programs. The Store was drawn without a window in all 13 languages (138 checks each, English, Japanese and Arabic included), and no icon, banner or preview in the program has the bytes of an old one (a test keeps the old marks out and holds the new ones to the website's files). It was run against the real update check with a manifest served from this machine (50 checks, 12 of them new for Tsubomi): with no Tsubomi block the card says Coming soon; with one it offers GET at 1.0.0 and does not install by itself; beside an Alpha module it refuses and leaves the folder unchanged; once installed it shows OPEN and updates itself to 1.0.1. The real Tsubomi 1.0.0 jar from this site went through the installer too: its thirteen Alpha module ids are found, it installs into a clean folder and is refused beside an Alpha module. The built application was driven in a real window twice: all 94 of the window instrument's claims held in each run, none failed, none were undecided. Perch's own instrument, on this build: 47 claims held in one run and 49 in the other, none failed, and three and one could not be decided because the machine was busy (Perch is unchanged since 3.0.0). The macOS installer, built by CI, was opened here and the app inside it run: it reports 3.0.2, its icon file is the one in the repository, and it draws all five screens with the new icons and a GET button on Tsubomi; it is built for Apple Silicon Macs only. Not verified, and worth saying: Tsubomi in a real Minecraft client (nobody has run it there yet); a Tsubomi download from this site through a real Store window (the real jar went through the installer directly, and the check against the update code used a copy served from this machine); how the refusal dialog's long sentence is laid out; that sentence is in English in every language, like the other install failures; the Windows and Linux installers, which nobody has installed or run; and the Tsubomi words in the twelve languages other than English, which are the ASTRAEA wording with the name swapped and which nobody who speaks them has read.

指南

Corvus 是一款小型桌面应用，自动让你的模组保持最新。它会到本 Wiki 查看当前版本，替你下载更新，并在触碰你的 mods 文件夹之前，用这里公布的 SHA-256 校验和核对每个下载的文件。本 Wiki 是它唯一信任的来源。

本指南是为较早版本的 Corvus 编写的。Corvus Store 3.0 的界面已更新，部分步骤可能不同。

Corvus 是什么，为什么要做它

手动保持模组最新，意味着每次发布新版本都要重新回到下载页，比对版本号，下载新文件，再放进正确的文件夹。Corvus 把这一切自动化：它读取本 Wiki 的发布清单，与你已安装的内容比对，只获取有变化的部分。

启动器的每一次下载，在使用之前都会与本 Wiki 公布的 SHA-256 校验和核对。下载的文件若不匹配，启动器就不会安装它。对于“当前”版本是哪一个，本 Wiki 是启动器唯一的依据。

Corvus 的安装方法

Corvus 可从本 Wiki 的下载页获取，有两种形式：

  • 各操作系统的原生安装程序（Windows 用 .msi、macOS 用 .dmg、Linux 用 .deb） —— 可以按与普通桌面应用相同的步骤安装，不需要 Java。由于我们尚未进行代码签名，首次启动时操作系统会显示警告。在 macOS 上，请不要双击，而是右键点击应用并选择「打开」。在 Windows 上，请在 SmartScreen 的警告中选择「更多信息」→「仍要运行」。
  • 跨平台的 jar corvus-3.0.2.jar —— 同一个文件在 Windows、macOS、Linux 上都能运行，但需要事先安装好 Java 25 或更高版本。如果双击打不开，请在下载该文件的文件夹中打开终端（或命令提示符），执行 java -jar corvus-3.0.2.jar。
指定已有的整合包文件夹

如果你已经手动安装了模组，不必重新开始。首次运行时，启动器会让你选择模组已经所在的文件夹，而不是新建一个。指向你现有的 mods 文件夹，启动器此后就会把那个安装视为自己管理的安装。

自动更新模式与手动更新模式的区别

在自动更新模式下，启动器会自行查阅本 Wiki 的发布信息，一旦有新版本公开就立即安装。您什么都不用做，整合包文件夹也会始终保持在最新状态。

在手动更新模式下，启动器仍会确认有没有更新，但在下载和安装之前会等待您确认。如果希望自己选择更新的时机，例如不想让更新打断正在进行的游戏，这个模式会很方便。

如何确认更新真的生效了

从 1.1.0 版起，按下 Update 后，新的 MOD 文件会被直接写入整合包的 mods 文件夹。在更新之后实际重新检查文件夹的内容、确认预期的文件确实存在之前，界面不会显示「Update complete」。如果中途出现任何失败，它会如实报告失败，而不是给出虚假的成功提示。

在 macOS 上实际确认的方法：打开“通用”界面中显示的那个文件夹（在 Finder 中按 ⌘+⇧+G 并粘贴路径），查看 mods 的内容，比对 Update 前后各个 cherry-*.jar 文件名中的版本号。

如果您是从最后一次由 1.1.0 之前版本的启动器改动过的整合包文件夹进行更新，那么仅限最初的 1 次，该 MOD 的旧版本 jar 有可能与新的 jar 并存（这是因为更早的启动器没有记录自己放置过哪些文件）。从下一次更新开始就会自动消除。如果您想马上处理，也可以在确认新文件确实存在之后，手动删除旧版本的 cherry-*.jar，这不会有问题。

更新失败时从备份还原

为了应对更新之后陷入 MOD 故障等不希望出现的状态，或者您想撤销这次更新的情况，启动器会把更新前整合包的状态保留为备份。请不要试图手动去修复文件，而是使用启动器的还原功能，把整合包文件夹恢复到备份时的状态。
