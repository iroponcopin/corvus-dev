Что нового · Версия 3.0.2

Corvus Store 3.0.2 is a small release with two changes.

Tsubomi can now be installed from the Store. Tsubomi is published as one jar rather than a package of several, and Corvus Store 3.0.0 and 3.0.1 did not know that shape, so its card said "Coming soon". The card now has a GET button like OUKA, Cherry, ASTRAEA and Aureum have. Pressing it downloads the jar, checks its size and SHA-256 against the site, and puts it in your mods folder; once it is installed, Tsubomi updates itself in place, and an installed copy is found by what the jar is, not by what the file is called. Tsubomi cannot run beside Alpha: its own jar says so, and Minecraft would refuse to start. So if your mods folder holds any Alpha module, the Store says so in one plain sentence that names the jars, and changes nothing. That applies to updates too.

The icons are the new ones. OUKA, Cherry, Aureum and Corvus Store itself now show the same icons as the website; they are the website's own files, not redrawn copies, and the big pictures on the Today cards of OUKA, Cherry and Aureum are the website's new banners. In a language that reads right to left the banner is arranged for it, with the emblem on the left and drawn as it is, not mirrored. The old marks are gone from the application, from the macOS, Windows and Linux installers' icons, and from the Today cards. One thing to know: the largest size inside the macOS icon is the 512 pixel logo enlarged, because 512 pixels is all the studio supplied.

Everything else is 3.0.1.

Verified: 933 unit tests pass, with the compiler set to refuse any warning, and two clean builds made byte-identical programs. The Store was drawn without a window in all 13 languages (138 checks each, English, Japanese and Arabic included), and no icon, banner or preview in the program has the bytes of an old one (a test keeps the old marks out and holds the new ones to the website's files). It was run against the real update check with a manifest served from this machine (50 checks, 12 of them new for Tsubomi): with no Tsubomi block the card says Coming soon; with one it offers GET at 1.0.0 and does not install by itself; beside an Alpha module it refuses and leaves the folder unchanged; once installed it shows OPEN and updates itself to 1.0.1. The real Tsubomi 1.0.0 jar from this site went through the installer too: its thirteen Alpha module ids are found, it installs into a clean folder and is refused beside an Alpha module. The built application was driven in a real window twice: all 94 of the window instrument's claims held in each run, none failed, none were undecided. Perch's own instrument, on this build: 47 claims held in one run and 49 in the other, none failed, and three and one could not be decided because the machine was busy (Perch is unchanged since 3.0.0). The macOS installer, built by CI, was opened here and the app inside it run: it reports 3.0.2, its icon file is the one in the repository, and it draws all five screens with the new icons and a GET button on Tsubomi; it is built for Apple Silicon Macs only. Not verified, and worth saying: Tsubomi in a real Minecraft client (nobody has run it there yet); a Tsubomi download from this site through a real Store window (the real jar went through the installer directly, and the check against the update code used a copy served from this machine); how the refusal dialog's long sentence is laid out; that sentence is in English in every language, like the other install failures; the Windows and Linux installers, which nobody has installed or run; and the Tsubomi words in the twelve languages other than English, which are the ASTRAEA wording with the name swapped and which nobody who speaks them has read.

Руководство

Corvus — небольшое настольное приложение, которое автоматически поддерживает ваши моды в актуальном состоянии. Оно проверяет на этой вики текущий выпуск, скачивает обновления за вас и перед тем, как тронуть папку mods, сверяет каждый скачанный файл с опубликованной здесь контрольной суммой SHA-256. Эта вики — единственный источник, которому оно доверяет.

Это руководство написано для прежних версий Corvus. У Corvus Store 3.0 новые экраны, поэтому некоторые шаги могут отличаться.

Что такое Corvus и зачем он создан

Поддерживать моды в актуальном состоянии вручную — значит при каждом выпуске снова заходить на страницу загрузки, сравнивать номера версий, скачивать новый файл и класть его в нужную папку. Corvus делает это сам: читает манифест выпусков этой вики, сравнивает его с тем, что у вас уже установлено, и скачивает только изменившееся.

Каждая загрузка лаунчера перед использованием проверяется по контрольной сумме SHA-256, опубликованной этой викой. Если скачанный файл не совпадает, лаунчер его не устанавливает. Эта вика — единственный источник истины лаунчера о том, какой выпуск «текущий».

Как установить Corvus

Corvus доступен на странице загрузки этой вики в двух видах:

  • Нативные установщики для каждой ОС (.msi для Windows, .dmg для macOS, .deb для Linux) — ставятся так же, как обычное настольное приложение, и Java для них не нужна. Подпись кода мы пока не оформили, поэтому при первом запуске ОС покажет предупреждение. В macOS вместо двойного щелчка щёлкните по приложению правой кнопкой и выберите «Открыть». В Windows в предупреждении SmartScreen выберите «Подробнее» → «Выполнить в любом случае».
  • Кроссплатформенный jar corvus-3.0.2.jar — один и тот же файл работает и в Windows, и в macOS, и в Linux, но заранее должна быть установлена Java 25 или новее. Если по двойному щелчку он не открывается, откройте терминал (или командную строку) в папке, куда вы его скачали, и выполните java -jar corvus-3.0.2.jar.
Указать существующую папку со сборкой модов

Если вы уже установили моды вручную, начинать заново не нужно. При первом запуске лаунчер позволяет выбрать папку, где ваши моды уже лежат, вместо создания новой. Укажите свою существующую папку mods, и лаунчер будет считать эту установку той, которой он управляет.

Чем отличаются автоматический и ручной режимы обновления

В автоматическом режиме обновления лаунчер сам сверяется со сведениями о выпуске на этом Wiki и устанавливает новую версию, как только она опубликована. Папка сборки остаётся в актуальном состоянии, а вам для этого ничего делать не нужно.

В ручном режиме обновления лаунчер по-прежнему проверяет наличие обновлений, но перед загрузкой и установкой ждёт вашего подтверждения. Это удобно, когда вы хотите сами выбирать момент обновления — например, чтобы оно не вклинилось посреди игры.

Как убедиться, что обновление действительно применилось

Начиная с версии 1.1.0, по нажатию Update новые файлы модов записываются прямо в папку mods вашей сборки. Надпись «Update complete» не появится, пока лаунчер после обновления действительно не перепроверит содержимое папки и не убедится, что нужные файлы на месте. Если что-то не удалось на полпути, он сообщит об ошибке, а не покажет ложный успех.

Как проверить это самому в macOS: откройте папку, показанную в разделе «Основные» (в Finder нажмите ⌘+⇧+G и вставьте путь), загляните в mods и сравните номер версии в имени каждого файла cherry-*.jar до и после нажатия Update.

Если вы обновляетесь из папки сборки, к которой последним обращался лаунчер версии старше 1.1.0, то ровно один первый раз рядом с новым jar может остаться jar с прежним номером версии того же мода (у прежних лаунчеров не было записи о том, какие файлы они сами положили). Со следующего обновления это устраняется само. Если хочется убрать это сразу, можно, убедившись в наличии нового файла, вручную удалить cherry-*.jar со старым номером версии.

Восстановление из резервной копии, если обновление не удалось

На случай, если после обновления сборка окажется в нежелательном состоянии — например, мод работает неправильно — или если обновление захочется отменить, лаунчер хранит резервную копию состояния сборки до обновления. Не пытайтесь чинить файлы вручную: воспользуйтесь функцией восстановления в лаунчере и верните папку сборки к состоянию на момент резервной копии.
