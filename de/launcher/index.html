Neuheiten · Version 5.5.1311

Corvus Store 5.5.1311 and Corvus Agent 5.5.1311 bring the following.

Corvus Store now also downloads Fabric API, which Punchy! needs, straight from Modrinth when it is missing from the mods folder. This happens only when you press Install for Punchy!, and the confirmation says so. A Fabric API you already have is never touched. If Fabric API cannot be downloaded or fails its check, Punchy! is not installed and nothing is left behind.

On macOS, Corvus Store follows the system's Reduce Transparency, Increase Contrast and Reduce Motion settings while it is running, without a restart. It shows the number of available updates and the progress of a download on its Dock icon. It gives a trackpad tap as the sliders click into each step and when you choose a model. It no longer waits for a macOS permission question before its window appears.

Corvus Agent 5.5.1311 has no functional change.

Known limits: the macOS features were checked on one Mac with test instruments, not by long use. Fabric API downloading was checked with a local stand-in, not yet with a real download through the Store. Windows and Linux do not use the macOS features.

Anleitung

Corvus ist eine kleine Desktop-App, die deine Mods automatisch aktuell hält. Sie fragt dieses Wiki nach der aktuellen Version, lädt Updates für dich herunter und prüft jede heruntergeladene Datei gegen eine hier veröffentlichte SHA-256-Prüfsumme, bevor sie deinen mods-Ordner anfasst. Dieses Wiki ist die einzige Quelle, der sie vertraut.

Diese Anleitung wurde für frühere Versionen von Corvus geschrieben. Corvus Store 3.0 hat neue Bildschirme, daher können einige Schritte abweichen.

Was Corvus ist und warum es Corvus gibt

Mods von Hand aktuell zu halten heißt, bei jeder Version wieder die Download-Seite aufzusuchen, Versionsnummern zu vergleichen, eine neue Datei herunterzuladen und sie in den richtigen Ordner zu legen. Corvus automatisiert das: Es liest das Versionsmanifest dieses Wikis, vergleicht es mit dem, was du bereits installiert hast, und holt nur das, was sich geändert hat.

Jeder Download des Launchers wird vor der Verwendung gegen eine von diesem Wiki veröffentlichte SHA-256-Prüfsumme geprüft. Passt eine heruntergeladene Datei nicht, installiert der Launcher sie nicht. Dieses Wiki ist die einzige Wahrheitsquelle des Launchers dafür, welche Version die „aktuelle“ ist.

So installierst du Corvus

Corvus gibt es auf der Download-Seite dieses Wikis in zwei Formen:

  • Native Installationsprogramme je Betriebssystem (.msi für Windows, .dmg für macOS, .deb für Linux) – sie installieren sich wie eine ganz normale Desktop-App, und Java brauchst du dafür nicht. Weil sie noch nicht signiert sind, zeigt dein Betriebssystem beim ersten Start eine Warnung. Unter macOS klickst du die App statt mit einem Doppelklick mit der rechten Maustaste an und wählst „Öffnen“. Unter Windows wählst du in der SmartScreen-Warnung „Weitere Informationen“ → „Trotzdem ausführen“.
  • Die plattformübergreifende jar-Datei corvus-5.5.1311.jar – ein und dieselbe Datei läuft unter Windows, macOS und Linux, dafür muss aber Java 25 oder neuer bereits installiert sein. Öffnet sie sich per Doppelklick nicht, öffne in dem Ordner, in den du sie heruntergeladen hast, ein Terminal (oder die Eingabeaufforderung) und führe java -jar corvus-5.5.1311.jar aus.
Auf einen vorhandenen MOD-Paketordner zeigen

Wenn du Mods bereits von Hand installiert hast, musst du nicht von vorn anfangen. Beim ersten Start lässt dich der Launcher den Ordner wählen, in dem deine Mods schon liegen, statt einen neuen anzulegen. Zeige auf deinen vorhandenen mods-Ordner, und der Launcher behandelt diese Installation ab dann als die, die er verwaltet.

Der Unterschied zwischen automatischem und manuellem Update-Modus

Im automatischen Update-Modus prüft der Launcher die Veröffentlichungsdaten dieses Wikis von sich aus und installiert eine neue Version, sobald sie erschienen ist. Dein Paketordner bleibt so immer auf dem neuesten Stand, ohne dass du etwas tun musst.

Im manuellen Update-Modus prüft der Launcher zwar, ob es eine Aktualisierung gibt, wartet vor dem Herunterladen und Installieren aber auf deine Bestätigung. Das ist praktisch, wenn du den Zeitpunkt selbst wählen möchtest, etwa um dir eine laufende Spielsitzung nicht von einer Aktualisierung unterbrechen zu lassen.

So prüfst du, ob eine Aktualisierung wirklich angekommen ist

Seit Version 1.1.0 schreibt ein Klick auf Update die neuen MOD-Dateien direkt in den mods-Ordner deines Pakets. „Update complete“ erscheint erst, wenn der Launcher den Inhalt des Ordners danach wirklich noch einmal geprüft und festgestellt hat, dass die erwarteten Dateien tatsächlich dort liegen. Geht unterwegs etwas schief, meldet er einen Fehlschlag statt eines falschen Erfolgs.

So siehst du es dir unter macOS selbst an: Öffne den Ordner, der unter „Allgemein“ steht (im Finder ⌘+⇧+G drücken und den Pfad einfügen), sieh in mods nach und vergleiche vor und nach dem Update die Versionsnummer in den Dateinamen der einzelnen cherry-*.jar.

Aktualisierst du einen Paketordner, den zuletzt ein Launcher älter als 1.1.0 angefasst hat, kann genau beim ersten Mal die jar-Datei mit der alten Versionsnummer dieses MODs neben der neuen liegen bleiben (die früheren Launcher hatten keine Aufzeichnung darüber, welche Dateien sie selbst abgelegt hatten). Ab der nächsten Aktualisierung erledigt sich das von allein. Wenn es dich sofort stört, kannst du die cherry-*.jar mit der alten Versionsnummer auch von Hand löschen, sobald du dich vergewissert hast, dass die neue da ist.

Aus einer Sicherung wiederherstellen, wenn eine Aktualisierung schiefgeht

Für den Fall, dass eine Aktualisierung einen Zustand hinterlässt, den du nicht willst – etwa einen MOD, der sich falsch verhält –, oder dass du sie rückgängig machen möchtest, hält der Launcher den Zustand des Pakets von vor der Aktualisierung als Sicherung bereit. Versuch nicht, die Dateien von Hand zu reparieren, sondern setze den Paketordner mit der Wiederherstellungsfunktion des Launchers auf den Stand der Sicherung zurück.
