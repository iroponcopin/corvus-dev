Novidades · Versão 5.0.3

Corvus Store 5.0.3 and Corvus Agent 5.0.2 follow the website to its new address.

The Corvus website has moved to iroponcopin.github.io/corvus-dev. The Store and the Agent now read updates there. If your Store or Agent was set to the previous address, it switches to the new one by itself the first time it starts; nothing needs to be changed by hand. The name of the website is now simply Corvus.

Everything else is 5.0.2 and 5.0.1.

Verified: the unit tests pass (603, 481 and 160 in the three modules), including new tests that a saved setting with the previous address is moved to the new one, in the Store and in the Agent, and that every link the Store opens points to the new site. Not verified, and worth saying: the new address was checked from the published site after release, not before it; earlier versions of the Store and the Agent keep working because the previous address still forwards the update information for now.

Guia

O Corvus é um pequeno aplicativo de desktop que mantém seus mods atualizados automaticamente. Ele consulta esta Wiki para saber a versão atual, baixa as atualizações para você e verifica cada arquivo baixado contra um checksum SHA-256 publicado aqui antes de mexer na sua pasta mods. Esta Wiki é a única fonte em que ele confia.

Este guia foi escrito para versões anteriores do Corvus. O Corvus Store 3.0 tem telas novas, então alguns passos podem ser diferentes.

O que é o Corvus e por que ele foi feito

Manter os mods atualizados à mão significa voltar à página de download, comparar números de versão, baixar um arquivo novo e colocá-lo na pasta certa a cada lançamento. O Corvus automatiza isso: ele lê o manifesto de versões desta Wiki, compara com o que você já tem instalado e baixa apenas o que mudou.

Cada download feito pelo lançador é verificado contra um checksum SHA-256 publicado por esta Wiki antes de ser usado. Se um arquivo baixado não corresponder, o lançador não o instala. Esta Wiki é a única fonte de verdade do lançador sobre qual é a versão «atual».

Como instalar o Corvus

O Corvus está disponível na página de download desta Wiki em duas formas:

  • Instaladores nativos para cada sistema operacional (.msi para Windows, .dmg para macOS, .deb para Linux) — a instalação segue os mesmos passos de um aplicativo de desktop comum e não precisa de Java. Como ainda não fizemos a assinatura de código, o sistema operacional mostra um aviso na primeira execução. No macOS, em vez de dar dois cliques, clique com o botão direito no aplicativo e escolha “Abrir”. No Windows, no aviso do SmartScreen, escolha “Mais informações” → “Executar assim mesmo”.
  • O jar multiplataforma corvus-5.0.3.jar — o mesmo arquivo funciona tanto no Windows quanto no macOS e no Linux, mas exige o Java 25 ou mais recente já instalado. Se ele não abrir com dois cliques, abra o Terminal (ou o Prompt de Comando) na pasta em que você baixou o arquivo e execute java -jar corvus-5.0.3.jar.
Apontar para uma pasta de pacote de MODs já existente

Se você já instalou os mods manualmente, não precisa começar do zero. Na primeira execução, o lançador deixa você escolher a pasta onde seus mods já estão, em vez de criar uma nova. Aponte para a sua pasta mods existente e o lançador passará a tratar essa instalação como a que ele gerencia.

A diferença entre o modo de atualização automática e o manual

No modo de atualização automática, o launcher confere por conta própria as informações de lançamento deste Wiki e instala as versões novas assim que elas são publicadas. Sem que você faça nada, a pasta do pacote fica sempre atualizada.

No modo de atualização manual, o launcher confere se há atualização, mas espera a sua confirmação antes de baixar ou instalar qualquer coisa. É útil quando você quer escolher o momento da atualização, por exemplo para evitar que ela interrompa uma partida.

Como conferir se a atualização foi mesmo aplicada

A partir da versão 1.1.0, ao apertar Update os novos arquivos de MOD são gravados diretamente na pasta mods do pacote. A mensagem “Update complete” só aparece depois que o conteúdo da pasta é de fato conferido de novo, após a atualização, e se confirma que os arquivos esperados estão mesmo lá. Se algo falhar no meio do caminho, ele reporta a falha em vez de exibir um sucesso falso.

Como conferir de verdade no macOS: abra a pasta mostrada na seção Geral (no Finder, aperte ⌘+⇧+G e cole o caminho), olhe dentro de mods e confira o número de versão dentro do nome de cada arquivo cherry-*.jar antes e depois do Update.

Se a atualização partir de uma pasta de pacote que foi mexida pela última vez por um launcher anterior à 1.1.0, só na primeira vez pode acontecer de o jar de versão antiga daquele MOD ficar ao lado do jar novo (porque os launchers anteriores não guardavam um registro de quais arquivos eles próprios tinham colocado). Isso se resolve sozinho a partir da atualização seguinte. Se você quiser resolver na hora, não há problema em apagar manualmente o cherry-*.jar de versão antiga, depois de confirmar que o novo está lá.

Restaurar a partir de um backup quando a atualização dá errado

Para o caso de a atualização deixar o pacote em um estado indesejado, como um MOD com defeito, ou de você querer desfazer a atualização, o launcher guarda como backup o estado do pacote de antes da atualização. Em vez de tentar consertar os arquivos na mão, use a função de restauração do launcher para voltar a pasta do pacote ao estado do backup.
